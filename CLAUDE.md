# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Networks.jl is a Julia port of the R `network` package from the StatNet ecosystem. It provides a `Network{T}` type that implements the Graphs.jl `AbstractGraph` interface while adding vertex, edge, and network-level attribute storage.

## Development Commands

```bash
# Run tests
julia --project -e 'using Pkg; Pkg.test()'

# Load package in REPL
julia --project -e 'using Networks'

# Strict docs build
julia --project=docs docs/make.jl

# Regenerate the bundled datasets from their upstream R objects (base R + `network`)
Rscript data/r/extract_datasets.R

# Regenerate the density golden fixture (base R + `network` + `sna`)
Rscript test/fixtures/r/network_density.R > test/fixtures/network_density.toml
```

## Architecture

**Core types** (`src/types.jl`):
- `AbstractNetwork{T} <: Graphs.AbstractGraph{T}` — abstract base type
- `Network{T,D}` — main mutable struct; `D::Bool` is compile-time directedness (`Graphs.is_directed` is truthful at the type level; `net.directed` is a read-only property returning `D`). Wraps a `SimpleDiGraph{T}` internally (even for undirected networks, which store both edge directions and halve `ne()`). The one-parameter UnionAll `Network{Int}` matches both; `Network{Int}(; n, directed=...)` picks `D` from the keyword
- `BipartiteNetwork{T}` — wraps a `Network{T}` with mode counts; vertices `1:n_mode1` are mode 1, rest are mode 2
- `_canonical_edge(net, i, j)` — returns `(i,j)` for directed, `minmax(i,j)` for undirected; used everywhere for edge attribute keying

**Source file organization**:
- `types.jl` — struct definitions, constructors (`Network()`, `network()`, `network_initialize()`; `n < 0` is an `ArgumentError`, as R's "cannot be of negative order"), display. **Display is a pair** (2026-09 round 3): `show(io, net)` is ONE line — `Network{Int64,true}(50 vertices, 113 edges)`, plus `, loops` / `, two-mode n₁+n₂` when they apply — because Base uses the 2-arg method inside containers and `load_dataset(:s50)`'s `NamedTuple` of a `Vector{Network}` printed as a garbled wall while the only method was multi-line; `show(io, MIME"text/plain"(), net)` (REPL, `display`) is the R-style block via `_show_network_block`, which states `Directed:`, `Loops:` and the two-mode size (`Two-mode: 2 mode-1 vertices (1:2), 4 mode-2 vertices (3:6)`) — the three things `print.network` always shows and students most often get wrong — with attribute names sorted as R lists them. `BipartiteNetwork` has the same pair, delegating to the wrapped network. Pinned by the "show: one line inside containers" testset
- `graphs_interface.jl` — Graphs.jl `AbstractGraph` method implementations (nv, ne, edges, add_edge!, etc.) plus utilities (density, neighborhood, induced subgraph, permute). `network_density(net; missing=:error, diag=net.loops, discount_bipartite=false)` is ONE implementation for `Network` and `BipartiteNetwork`, pinned to R `network.density` by `test/fixtures/network_density.toml`: it guards with `require_observed` (`:face` = R's `na.omit=FALSE`; R's `na.omit=TRUE` is deliberately absent), `diag` defaults to the `loops` flag exactly as R keys on `has.loops` (so `diag=false` on a loops network is `sna::gden(diag=FALSE)`: self-loops leave numerator and denominator), and `discount_bipartite=true` is R's cross-mode denominator `n₁·n₂` (`2·n₁·n₂` directed). The fixture (which needs `sna` as well as `network` and records `sna_version`) pins `diag=false` to `sna::gden(diag=FALSE)` on loops networks where the default and `diag=false` values differ; `sna::gden(diag=TRUE)` is deliberately not recorded (undirected: matrix sum over n², not `network.density`'s n(n+1)/2). The `BipartiteNetwork` method forwards explicit keywords, not a `kwargs...` splat (which allocated 16–32 B), and splits on `net isa Network{T,true}` because the wrapper's `network` field is typed `Network{T}` (directedness unknown at the field level — a plain forward dispatches dynamically, 48 B); both methods are 0 B and the testset pins it. `rem_edge!`/`add_edge!` are the sampler toggle and are allocation-free: early return on an absent edge, attribute store skipped when empty and walked by value otherwise, concrete `SimpleEdge{T}` handed to Graphs.jl (the generic `add_edge!(g, x, y)` allocates); the residual alternating 48–96 B on `add_edge!` is Base `insert!` re-growing the adjacency `Memory` after `deleteat!` and is identical on a bare `SimpleDiGraph` — the testset asserts equality rather than zero.
- `attributes.jl` — get/set/delete/list for vertex, edge, and network attributes; also `Base.getindex`/`setindex!` overloads for `net[:v, :attr]` syntax. **Setters validate their targets** (2026-09 round 2, mirroring R's "vertex IDs out of range"): `_check_vertex(net, v, fname, attr)` throws an `ArgumentError` for a vertex outside `1:nv(net)` in the single-vertex and `Dict` forms of `set_vertex_attribute!` and for either endpoint of the single-edge `set_edge_attribute!`, which also requires `has_edge(net, i, j)` unless `require_edge=false` (the documented opt-out for storing a value ahead of the edge; NetworkDynamic's "Network extraction" testset does exactly that and is a pending cross-repo request). The message is built only on failure so the setters stay cheap in ERGMCount's per-proposal sampler calls. `vertex_attribute_vector` without `default=` throws an `ArgumentError` naming the attribute and the vertex — and listing the attributes that exist when the name is unknown — instead of a bare `KeyError(i)`. `network_from_edgelist` (coercion.jl) likewise throws on an endpoint outside `1:n` or a self-loop under `loops=false` rather than letting `add_edge!` return `false` unnoticed. **Round 3 closed the gaps the graders found in that rule**: the `Dict` form of `set_edge_attribute!` now validates exactly like the single-edge form (both endpoints, `has_edge` unless `require_edge=false`, all-or-nothing via `_not_an_edge_error`, the one message both forms share); `add_edges!` (graphs_interface.jl), the bulk adder every example uses, throws on an endpoint outside `1:nv(net)`, a self-loop under `loops=false` and a within-mode pair on a two-mode network (a repeat counts 0; the single `add_edge!` keeps Graphs.jl's `Bool`); `as_matrix(net; attr=)` / `as_edgelist(net; attrs=)` throw via `_check_edge_attr` on an edge attribute the network does not have, listing the ones it does (an all-zero matrix used to feed QAP silently; R's `as.sociomatrix` warns); `get_induced_subgraph` refuses an out-of-range or repeated vertex and `permute_vertices` a non-permutation (`isperm`), both R errors. All pinned by the "Common mistakes are actionable" testset
- `missing.jl` — missing-dyad (unobserved tie) mask: `set_missing_dyad!`, `is_missing_dyad`, `delete_missing_dyad!`, `clear_missing_dyads!`, `missing_dyads`, `n_missing_dyads`. A masked dyad means tie status is UNOBSERVED (distinct from 'no tie'); the graph keeps a face value that structural queries report. Stored as a `Set{Tuple{T,T}}` field keyed by `_canonical_edge` (O(1) lookup, symmetric for undirected). Survives `copy` and is remapped by `rem_vertex!`/`get_induced_subgraph`/`permute_vertices`.

  Also hosts **the ecosystem missing-data contract**, which every downstream package is expected to honour:
  - `supports_missing(x) -> Bool` — the trait a routine opts into (`supports_missing(::typeof(f)) = true`). Default `false`: a routine that has never thought about missingness is one that must refuse to see it.
  - `require_observed(net, policy=:error; context, face_ok=true)` — the guard a routine calls. Returns `net` when there is no mask or when `policy === :face` (the explicit, auditable opt-in to face values); throws an `ArgumentError` naming `context` otherwise. `MISSING_POLICIES == (:error, :face)`.

  The rule the contract enforces: **no exported routine may return a number computed from the face value of an unobserved tie unless the caller asked for it in writing.** Silently reading face values is what turns a partially observed network into plausible, wrong output.

  - `missing_policies(f) -> Tuple{Vararg{Symbol}}` — the routine-level vocabulary: the policies `f`'s `missing=` keyword *actually* takes. Default `(:error,)` (no keyword, no escape hatch); `network_density` declares `(:error, :face)`; a package with its own vocabulary (ERGM's `:condition_on_face`) declares it here. The capability-matrix generator prints this instead of a literal; the "Missing-data contract" testset checks that every exported Networks routine with a `missing=` keyword (`Base.kwarg_decl`) declares at least two policies.

  **`:face` is NOT offered everywhere, and should not be.** It is a real option only where reading a face value is a defensible (if lossy) analysis — the SNA descriptive measures, `mcmle`'s `:condition_on_face`, and the conversion adapters. For an estimator like TERGM, ERGMCount or ERGMMulti, a `:face` fit would enumerate unobserved dyads as *observed* rows of a pseudo-likelihood, which is precisely the silent data-invention the contract exists to stop; those routines expose no `missing=` keyword at all and pass `face_ok=false`, so the error message does not advertise an escape hatch the caller cannot take. (This gap was found by the generated capability matrix, which introspects `Base.kwarg_decl` rather than trusting the prose — only 3 of 13 fitting functions accept `missing=`.)
- `coercion.jl` — conversions: `as_matrix`, `as_edgelist`, `as_dataframe`, `network_from_matrix`, `network_from_edgelist`, `network_from_dataframe`. On a two-mode network `as_matrix` returns the `n₁ × n₂` incidence matrix by default and the `(n₁+n₂)`-square adjacency under `expand_bipartite=true` (R's `expand.bipartite=`), through the same dense/sparse path as a one-mode network so `attr=`/`missing_value=`/`return_mask=` apply to both shapes (SNA's matrix measures need the square form). **On a DIRECTED two-mode network the incidence matrix holds mode-1 → mode-2 arcs only** (2026-09 round 3): an arc with `src > k`, and a mask on such a dyad, has no cell, so `_as_incidence_matrix` and the `indices()` remap of `_as_matrix_missing_aware` drop it and `_warn_dropped_reverse` says how many went and points at `expand_bipartite=true` — exactly R's `as.matrix.network` (which drops silently; verified against network 1.20.0: arc 5→1 absent from the 2×4 matrix, present at `[5,1]` of the expanded one, the NA on 6→2 likewise). It used to be swapped into `B[1, col(5)]`, i.e. reported as the arc 1→5. The swap survives for undirected networks only, where it is a no-op (`edges` already yields `src <= dst`). Matrix conversion is **mask-aware**: `as_matrix(net; missing_value=missing)` writes `missing` at masked dyads (mask survives the round-trip, face value does not — the `missing` overwrote it), while `as_matrix(net; return_mask=true)` returns `(A, mask)` and pairs with `network_from_matrix(A; missing_mask=mask)` for a **fully lossless** round-trip preserving both mask and face value. `network_from_matrix` reads `missing` entries back into the mask. `sparse=true` + `missing_value` throws (a sparse matrix cannot distinguish a masked dyad from a structural zero)
- `conversion.jl` — **the ecosystem conversion contract**, the sibling of the missing-data contract. The network stack has adapters running in every direction (`Network` ↔ `DynamicNetwork`, `DynamicNetwork` → snapshots / contact sequences / relational-event sequences, `Network` → Siena matrices) and each maps a rich source onto a target that holds *less*. The rule:

  1. **Preserve what the target can represent.** A field that *can* survive must survive. Silently dropping representable metadata is never acceptable.
  2. **Reject or policy-gate what it cannot.** Missing-dyad masks are rejected by default (`require_observed(net, missing; context)`, the standard `:error`/`:face` policies), because "unobserved" silently becoming "absent" is the exact failure the missing-data contract exists to prevent.
  3. **Report what was dropped.** Every lossy conversion takes `report::Bool=false` and with `report=true` returns `(result, ::ConversionReport)`.

  Networks.jl owns only the *vocabulary* — `ConversionReport(source, target)`, `record_drop!(rep, field, why)`, `is_lossless`, `dropped_fields` — and knows nothing about `DynamicNetwork`, contacts or events; each adapter builds its own report. The per-path invariant table (what each path preserves / transforms / drops-with-policy / rejects, across directedness, loops, vertex+edge+network attributes, the missing-dyad mask, two-mode metadata, the observation window, spells including overlapping and point spells, and actor presence) is published in `docs/src/guide/conversion_invariants.md`. Pinned by the "Conversion contract: ConversionReport" testset here and by the "Conversion invariants" testsets in NetworkDynamic.jl, TSNA.jl, REM.jl and Siena.jl.
- `io.jl` — Pajek (.net) read/write, GraphML write, CSV edge list write
- `bootstrap.jl` — the ecosystem-shared **resampling loop**: `bootstrap_cov(refit, simulate, θ̂; n_boot, rng, threaded)` draws `n_boot` replicate datasets through the caller's `rng`, refits on each (threaded), and returns `(vcov, se, replicates)`. This is the ONE bootstrap of the ecosystem: the parametric bootstraps of `ERGM.mple`, `ERGMCount.count_mple`, `ERGMRank.fit_ergm_rank` and `ERGMMulti.ergm_multi` (`se=:bootstrap`: simulate at θ̂, refit, empirical covariance) and `REM.fit_rem`'s repeated draw of the case-control risk set (`se=:bootstrap`: the callbacks resample the *sampling design*, not the model, and REM combines the returned between-draw covariance with the average within-draw covariance by the law of total variance) all supply the two callbacks and reimplement nothing. Also hosts `check_se(se, allowed; context)`, the ONE validator of the `se=` keyword (returns `se` or throws `ArgumentError("<context>: se must be one of (...) (got :x)")`), replacing the seven hand-typed `se in (...) || throw` lines across the fitters (panel 2026-09, item 28).

  **It lives here, not in ERGM.jl** — and the sibling shared optimizer `newton_fit` (`newton.jl`) followed it here in 2026-09 — because REM.jl deliberately does not depend on ERGM.jl, and Networks.jl is the one foundation all five packages share. The four packages had *no* robust standard-error option at all before this (issue #9), and the alternative was pasting the same loop into four modules, which is itself one of the review's findings. Replicates are opaque to the loop (a network, a DataFrame, an `(index, data)` pair — REM uses the last so each threaded refit can stash its within-draw covariance), and all randomness flows through `simulate`, so a fixed `rng` reproduces the standard errors exactly and the threaded refits are thread-count-independent. Stdlib-only (Random, Statistics, LinearAlgebra).
- `results.jl` — also hosts **the ecosystem tied-event contract**, the third sibling of the missing-data and conversion contracts, for the models with an event clock (REM.jl, Relevent.jl; review finding 12):
  - `TIE_POLICIES == (:error, :ordered, :breslow, :efron, :batch)` — the vocabulary of the shared `ties=` keyword. One set of symbols, one meaning per symbol, so `ties=:efron` cannot mean two things in two packages.
  - `check_tie_policy(ties, supported; model, reasons)` — the guard a fitter calls. Returns `ties` when the model supports it; otherwise throws, naming the model, **why** the policy does not apply to it, and what is supported instead.

  The rule the contract enforces: **an exact-time or exact-order likelihood defaults to `:error` on tied data, and a policy a model cannot honour fails loudly rather than no-ops.** Ordering a tie in a relational-event model does not merely pick a sort — the statistics are read off the pre-event state, so the event placed first enters the *statistics* of the event placed second. `tie_method(fit)` reports the policy that actually **ran** (hence `:none` when the data had no ties, and never `:error`, which throws instead of returning a fit). Not every symbol is defined for every likelihood: `:breslow`/`:efron` are corrections to a *partial* likelihood and are undefined for an exact-time hazard model, while `:batch` is meaningless in an ordinal likelihood (with the risk set frozen it *is* Breslow). Pinned by the "Tied-event contract" testset here and by the tie testsets in REM.jl and Relevent.jl.
- `results.jl` — the ecosystem-shared result-presentation layer: `print_coeftable` (R-style Estimate/Std.Error/z/p table with significance codes; `std_errors=nothing` drops the Std.Error column and makes `z_values=` mandatory with a 3-tuple `header`, `p_floor=` is forwarded to `format_pvalue` so a permutation test passes `1/reps` and prints `<0.001`, never `0.0` — panel 2026-09, item 15), `CoefficientTable` (the inspectable form of the same table — exactly the vectors `print_coeftable` consumes plus `header` and `p_floor`, `z`/`p` filled from `z_pvalues` when omitted, `show` delegates to `print_coeftable`, rows by index or name as NamedTuples; deliberately not named `CoefTable` so `using Networks, StatsBase` is never ambiguous), `z_pvalues` (the ONE z → two-sided-normal-p helper: `erfc(|z|/√2)` from SpecialFunctions, floored at `floatmin(Float64)` for finite `z`, NaN-aware; `z_pvalues(est, se)` returns `(z=, p=)` with `z = NaN` where `se ≤ 0` or NaN — replaces the five copies the 2026-09 panel found, item 13), `format_pvalue`/`signif_code` (floored at `<1e-16`, never `0.0`), `mc_pvalue` (`(1+k)/(N+1)` Monte-Carlo p-value), `GOFStatistic`/`GOFResult` containers with formatted `show`, and the empty `gof` generic that every model package extends (Printf + Statistics + SpecialFunctions' `erfc`)
- `statsapi.jl` — **the ecosystem StatsAPI surface** (panel 2026-09, item 15). Every fitted-model type answers `coef`, `stderror`, `vcov`, `confint`, `loglikelihood`, `nobs`, `dof`, `aic`, `bic` and `coeftable` wherever the quantity exists, each defined by the package on its OWN type (`StatsAPI.coeftable(fit::ERGMResult) = CoefficientTable(...)`). Networks.jl defines NO method on any StatsAPI generic (no fitted-model type, no piracy); it `import StatsAPI: coeftable` and re-exports it so that `Networks.coeftable === StatsAPI.coeftable` and `using Networks, REM` leaves the verb defined (REM exports the same binding), and hosts `check_statsapi(fit; required=STATSAPI_VERBS, strict=false) -> NamedTuple{required, Bool}`: `hasmethod(StatsAPI.<verb>, Tuple{typeof(fit)})` per verb, plus consistency of what exists (`length(coef) == length(stderror) == size(vcov, 1) == size(vcov, 2)`, `coeftable(fit) isa CoefficientTable` with one row per coefficient, a method that throws counts as absent); `strict=true` throws an `ArgumentError` naming every missing/inconsistent verb, so a package testset pins its surface with `@test check_statsapi(fit; strict=true) !== nothing`. The site's migration page derives its StatsAPI table from this rather than from prose.
- `newton.jl` — the ecosystem-shared **Newton optimizer** and **logistic-likelihood kernel** (panel 2026-09, item 14; moved from `ERGM.jl/src/estimation/newton.jl`; ERGM.jl now does `import Networks: newton_fit, logistic_derivatives` + `export`, so `ERGM.newton_fit === Networks.newton_fit`). `newton_fit(f, θ0; maxiter=100, tol=1e-8, max_halvings=10)` returns `(θ, se, vcov, loglik, converged, iterations)`; `f(θ) -> (ll, grad, hess)`. Two rules distinguish it from the copies it replaces: **a step at which `ll` is not finite is never taken** (halved like a decrease; if every halving is non-finite the loop stops at the last finite iterate with `converged=false`; non-finite `ll` at `θ0` is an `ArgumentError`), and **the covariance comes from diagonally equilibrated information** — its smallest eigenvalue must exceed `p * eps(Float64)` times its largest before Cholesky inversion; this numerical-rank criterion is invariant to individual coefficient units. If that fails, `@warn "... not negative definite"` and `se`/`vcov` are `NaN`, with `converged=false`, never the finite nonsense `sqrt.(abs.(diag(pinv(-hess))))` gave at a saddle. **The convergence verdict is scale-free** (round 3): beside `norm(grad) < sqrt(tol)` — a criterion in the gradient's own units, which on a 3 000-row CMPLE design or ERGMRank's swap design sits below the objective's rounding floor — the Newton decrement `½ ∇ℓᵀ(−H)⁻¹∇ℓ` (the gain the full step could still make, in the units of `tol`) is checked before every step: when `0 ≤ decrement < tol` the FULL step is taken (the polish R's glm performs at the same point; it must be finite and lose no more than `max(tol, 8·eps(|ll|))`) and the fit is converged at the polished point — never after a halved step, which would leave the gradient half-way. A step whose objective decreases by at most `8·eps(|ll|)` while the gradient norm shrinks is accepted (rounding noise is not descent). If every halving finds only a finite *decreasing* objective, `θ` stays put and `converged = norm(grad) < sqrt(tol)`. Pinned by the "scale-free verdict" testset (a deterministic k-ulp rounding penalty around the optimum of a Hessian-10⁶ quadratic); TERGM's `_polish_newton` and ERGMRank's `_stalled_at_optimum` shims were deleted when this landed. **Only a failed factorisation is "no Newton direction"**: the step's `try` catches `SingularException`/`LAPACKException`/`ZeroPivotException`/`PosDefException` and rethrows everything else (a bare `catch` used to report a `DimensionMismatch` or an interrupt as `converged=false`), and the first evaluation checks `length(grad) == p` and `size(hess) == (p, p)` because `\` broadcasts 1×1 and diagonal shapes instead of throwing. `logistic_derivatives(X, y::AbstractVector{Bool}; offset, weights)` and the binomial-row form `logistic_derivatives(X, n_tot, n_one; offset)` are ONE kernel (`_logistic_closure`: binary = binomial with `n_tot = weights` (or 1), `n_one = n_tot·y`; `off` is a `Union{Nothing,Vector{Float64}}` argument so each specialization captures it concretely). Workspaces (`η`, `resid`, `WX`) are allocated once; an evaluation allocates exactly the returned `Vector{Float64}(p)` + `Matrix{Float64}(p,p)`, and the "Shared Newton optimizer" testset pins that by `@allocated` equality. Both names are `public`, NOT exported: `ERGM.jl/test/runtests.jl` does `using ERGM; using Networks` and calls `newton_fit` unqualified, so a second export would be ambiguous there until ERGM aliases. Stdlib LinearAlgebra only (`cholesky`, `Symmetric`, `mul!`, `norm`, `issuccess`).
- `statistics.jl` — the ecosystem-shared **statistic protocol**: the empty generics `compute` (evaluate a statistic), `name` (its display label) and `compute_all` (sweep a set of them). Networks.jl defines no methods and knows nothing about what a statistic *is*; every model package extends these three with methods for its own statistic types (`compute(term, net)` in ERGM.jl, `compute(term, net, prev_net)` in TERGM.jl, `compute(stat, state, sender, receiver)` in REM.jl, ...). The signatures differ, so the methods coexist on one function.

  This is the same move as `gof`, made for the same reason. ERGM.jl and REM.jl each used to define and export *their own* `compute` and `name` — two different functions with one name — so `using ERGM, REM` (model cross-sections with ERGM, dynamics with REM: the core statnet workflow) left the unqualified verbs **undefined**, which is Julia's rule for conflicting exports. One generic cannot collide with itself. The rule for the ecosystem: **a verb that more than one package needs is defined once, here, and imported by name (`import Networks: compute, name`) wherever methods are added** — never redefined locally. Pinned by the "Shared statistic protocol" testset here and the "Namespace: co-loading ERGM and REM" testset in REM.jl.
- `datasets.jl` — `load_dataset(::Symbol)` for the six bundled teaching datasets, parsed from TSV files in `data/` with two hand-rolled readers (`_read_tsv` for header-bearing tables, `_read_int_matrix_tsv` for header-less integer matrices; no CSV dependency). Three return a `Network`: `:florentine_marriage`, `:florentine_business`, `:sampson`, and (2026-09, item 22) `:faux_mesa_high` — statnet's simulated 205-student school, `Network{Int,false}`, vertex attributes kept in statnet's spelling `:Grade`/`:Race`/`:Sex` so `nodematch("Grade")` translates. Two return a documented **NamedTuple** because a panel or an event stream is not one network: `:s50` → `(friendship::Vector{Network{Int,true}} (3 waves, 113/116/122 ties), alcohol::Matrix{Int} 50×3 coded 1–5, smoke::Matrix{Int} 50×3 coded 1–3)`, the RSiena data every Siena.jl example uses; `:wtc_police_calls` → `(events::Matrix{Int} 481×3 (number, sender, receiver — ordinal, no clock), n_actors = 37, is_icr::Vector{Bool})`, relevent's WTC radio calls for REM.jl/Relevent.jl. `_DATASET_NAMES` is the one list the unknown-name error prints. The three new datasets are produced by the checked-in `data/r/extract_datasets.R` (base R ≥ 4.5 + `network` only: downloads `faux.mesa.high.RData` from statnet/ergm and `relevent_workshop.Rdata` from statnet/Workshops — the CRAN `relevent` tarball ships no data — and reads s50 from RSiena when installed, else from Siena.jl's CSV copies); `data/README.md` records source URL, SHA-256 of every upstream and written file, upstream version, licence, citation and variable coding per dataset. Every load returns a fresh object (no caching; the testset checks two loads do not alias). Cross-checks: faux.mesa.high's same-grade tie count 163 is ERGMEgo's provenanced `fauxmesa_ego_census` target; s50 matrices are those `Siena.jl/test/fixtures/s50_siena07.toml` was generated from (RSiena 1.6.6)

**Undirected network pattern**: Undirected networks (`Network{T,false}`) use a `SimpleDiGraph` internally with edges stored in both directions. `ne()` halves the stored arc count (counting self-loops, stored once, exactly once), `edges()` yields each edge once via a length-carrying `UndirectedEdgeIter` (`src <= dst`), and `has_edge()` checks both directions. Because `Graphs.is_directed(Network{T,false}) == false`, Graphs.jl trait-dispatched generics (density, degree, connected_components, ...) give correct undirected answers.

**Bipartiteness**: `Graphs.is_bipartite` computes the graph-theoretic two-colorability property; the statnet-style two-mode metadata flag (`network(n; bipartite=k)`) is exposed via `is_two_mode`.

**Module/type naming**: The **module is `Networks`** (plural); the **type it exports is `Network`** (singular). So `using Networks; Network(5)` works — the constructor is callable by its documented name.

Until v0.2 the module was also called `Network`, and because a module and its type cannot share a name in Julia, the exported type shadowed the module. That caused three separate defects, all now gone:
- `Network(5)` threw `MethodError: objects of type Module are not callable` — the first thing a user tries.
- Qualified access like `Network.supports_missing(...)` inside a *dependent* package resolved to **field access on the type** (a `UnionAll`) and failed to precompile with a `FieldError`. This broke working code, not just ergonomics.
- The docsystem needed a `Base.Docs.doc!(::Type{Network}, ...)` method reaching into Base internals, and precompilation warned that docs for `Network.Network` were being replaced.

The type name was kept (it appears in ~200 downstream signatures); only the module moved. `test/runtests.jl` pins all three behaviours in the "Module/type names" testset.

## Key Dependencies

- **Graphs.jl** — provides `AbstractGraph` interface, `SimpleDiGraph` as internal storage
- **DataFrames.jl** — weak dependency; `as_dataframe` and `network_from_dataframe` methods are provided by the `NetworkDataFramesExt` package extension (`ext/`), active only when DataFrames.jl is loaded
- **SparseArrays** — sparse matrix support in `as_matrix`
- **SpecialFunctions.jl** (compat `"2"`) — `erfc` for `z_pvalues`. The ONE non-stdlib numerical dependency of the foundation, chosen deliberately (2026-09, item 13): a hand-rolled `erfc` is a correctness liability, and Distributions.jl (whose `ccdf(Normal(), z)` is the same `erfc` underneath) pulls in a far larger tree. Distributions is a **test-only** extra, used as the reference the `z_pvalues` testset compares against at 1e-12.
- **StatsAPI.jl** (compat `"1.7"`) — the `coeftable` generic that Networks re-exports (and the other nine verbs `check_statsapi` asks `hasmethod` about). Dependency-free (LinearAlgebra only), so it costs the foundation nothing; StatsBase, with its `CoefTable`, is deliberately NOT a dependency (2026-09, item 15).
- **LinearAlgebra / Random / Statistics** (stdlib) — `newton.jl` (`cholesky`, `Symmetric`, `mul!`, `norm`) and `bootstrap.jl`

## Conventions

- Attribute names are `Symbol`s; vertex attrs stored as `Dict{Symbol, Dict{T, Any}}`, edge attrs as `Dict{Symbol, Dict{Tuple{T,T}, Any}}`
- Typed attribute accessors (`get_vertex_attribute(net, attr, V)`, `vertex_attribute_vector(net, attr, V; default)`, `get_edge_attribute(net, attr, V)`) convert once and return concretely typed containers — the fast path for model code; the untyped accessors stay unchanged
- Mutating functions end with `!` (Julia convention)
- Functions mirroring R's statnet API use snake_case with `network_` prefix (e.g., `network_density`, `network_initialize`, `network_from_matrix`)
- Constructor aliases: `Network(n)`, `network(n)`, and `network_initialize(n)` all create the same thing. `Network(n)` is the documented primary constructor and is callable after a plain `using Networks`; the lowercase `network(n)` is the statnet-style alias (and was the only working form before the v0.2 module rename, so it is what the existing test suites use).
- Networks default to `directed=true`, `loops=false`
- Tests use flat `@testset` blocks in a single `test/runtests.jl` file; no separate test files
- Docs build with Documenter via `docs/make.jl` (strict: `warnonly=false`, `checkdocs=:exports`). **Julia 1.12 stays the floor** (decision 2026-09, closing site issue #3): the original "struct shadows the module" reason went away with the `Networks` rename, but the package now uses the `public` keyword (`public newton_fit, logistic_derivatives`, Julia ≥ 1.11) and `Base.kwarg_decl`-based introspection in the missing-policies sweep and the capability generator, and the ecosystem's CI matrix (`'1.12'`, `'1'`, `nightly`) is built around it. `CI.yml` runs the `'1'`/ubuntu cell with `JULIA_NUM_THREADS: 4` so the threaded `bootstrap_cov` thread-count-independence test is genuinely multi-threaded there
- `multiple` (parallel edges) and `hyper` (hyperedges) are NOT supported; the constructor throws on `multiple=true` or `hyper=true` rather than silently collapsing data
- `rem_vertex!` follows Graphs.jl swap-and-pop and remaps the renumbered last vertex's attributes (vertex and incident-edge) onto its new ID
- Bipartite networks reject within-mode edges in `add_edge!` and return an `n_mode1 × n_mode2` incidence matrix from `as_matrix` (`expand_bipartite=true` for the square adjacency); `network_density` on them defaults to R's all-dyads denominator, `discount_bipartite=true` for the cross-mode one
- **StatsAPI surface convention**: a model package `import StatsAPI: coef, stderror, vcov, confint, loglikelihood, nobs, dof, aic, bic, coeftable` (whichever exist for the model), defines each on its own result type, returns a `CoefficientTable` from `coeftable`, `export`s the verbs it defines, and asserts `check_statsapi(fit; strict=true) !== nothing` (or with a `required=` subset naming what the model legitimately has) in its testset. Never define `coeftable` as a new function — it must be the `StatsAPI` binding, which `using Networks` already provides.
- **Every exported and `public` docstring carries a fenced `julia` example** (2026-09 round 3; 67 of 107 had none, which a `checkdocs=:exports` build cannot see). The "Every exported and public docstring carries a runnable example" testset walks `Base.Docs.meta(Networks)` over `names(Networks)` and fails on any Networks-owned docstring without a ```` ```julia ```` or ```` ```jldoctest ```` block — so a new export needs an example, not just a sentence. The Graphs.jl re-exports (`nv`, `ne`, `degree`, …) are covered because their docstrings are attached from this module
- The export list is FROZEN by the "Exported API inventory" testset: `names(Networks)` (which on Julia ≥ 1.11 lists exported AND `public` names) is split by `Base.isexported` and checked against two literals, `frozen` (exported; includes `CoefficientTable`, `coeftable`, `check_statsapi` since 2026-09) and `frozen_public` (`[:logistic_derivatives, :newton_fit]`). Adding or removing either kind of name means editing the literal, the CHANGELOG, and ERGM/SNA's curated re-export lists. `degree`/`indegree`/`outdegree` are re-exported Graphs.jl bindings. The golden harness, `bootstrap_cov` and `record_drop!` stay exported (ten dependant suites call `load_golden` unqualified). The `public` block in `src/Networks.jl` holds the shared optimizer; ERGM and SNA use curated re-export lists; ERGM intentionally re-exports the shared optimizer, while SNA keeps it internal
- `load_golden(path; root=nothing)` resolves `provenance.script` by walking up the ancestors of the fixture's directory (or of `root=`) until `joinpath(dir, script)` is a file — the fixture's own directory first (ad-hoc `r/<name>.R`), the package root a few levels up (the conventional `test/fixtures/r/<name>.R`) — and throws an `ArgumentError` naming the fixture, the script string and every directory searched when none matches. The resolved absolute path is the `script_path` field of `GoldenFixture` (the struct has no external constructor; it is filled only by `load_golden`) and is printed by `show` and `golden_report`. The ecosystem validation checks that every checked-in fixture resolves its generator
